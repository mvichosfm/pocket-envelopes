## Executive summary

The app is in good shape where it has been audited before: the forecast arithmetic (decisions #22–#34) held up, the persistence model (#29–#31) held up, and no finding violates a documented invariant. What the pass turned up is concentrated in three seams that earlier audits did not cover. **First, the undo contract is applied unevenly**: "Fund the month" — the largest monthly mutation — plus Move funds, Update value, account/recurring edits and the reserve-flag cascade all mutate without `pushUndo`, so Ctrl-Z after them silently reverts something else (exactly the decision #11 failure). **Second, the recurring-coverage netting (decision #23) has a hole**: a `once` recurring or one whose `endDate` has passed keeps netting its full amount off the envelope's allowance forever, so the forecast, the dashboard low tile and the Fund modal all turn optimistic by a whole monthly budget per affected envelope. **Third, the reporting layer disagrees with the balances layer** in three separate ways — sweeps and Move-funds are counted as spending, future-dated rows are counted as spent, and the 12-month table drops or duplicates months on the 29th–31st. Beyond those, the serve.py private-path guard is bypassed by percent-encoding, there is no Host check, a crafted data file can inject script through unescaped ids, and a cluster of accessibility gaps (focus lost on every render, unlabelled Settings controls, drag-only reordering, toast-only validation) would fail a WCAG AA pass. No Critical findings. Two High, twenty-five Medium, thirty-two Low.

## High

**"Fund envelopes" books a batch of refill transactions with no undo snapshot** — logic, `pocket-envelopes.app:4503-4548`
`refillEnvelopes()`'s `rf_save` handler pushes one `income` tx per ticked envelope and calls `saveDirty()`; there is no `pushUndo()` anywhere between L4327 and the save. Every other batch mutation (close-out L4753, due review L3296, CSV import L5423, bulk edit L5115) snapshots first. After funding ten envelopes, Ctrl-Z pops an unrelated earlier snapshot and reverts *that* while the refills survive on the server — the decision #11 failure mode on the single largest monthly mutation. **Fix:** once `fundings.length > 0` is known and the soft-block confirm has passed, call `pushUndo(\`Fund ${plural(fundings.length, 'envelope')}\`)` immediately before the `[data-rf]:checked` push loop, and attach `{ label: 'Undo', onClick: performUndo }` to the success toast. Guard so a zero-row save leaves no no-op snapshot. _Cross-check: new concrete bug inside the tracked undo area (decisions #8/#11/#13a)._

**A `once` or ended recurring nets its full amount off the envelope allowance every month, forever** — correctness + logic (merged), `pocket-envelopes.app:2139-2169, 2445-2450, 2468-2472`
`recurringMonthlyEquiv` falls to `default: return a` for `schedule === 'once'`, so a one-off is valued as a monthly stream; `recurringMonthlyForEnvelope` and the `coveringRecs` set in `forecastAccountBalances` filter only on `active === false` and never read `endDate` or `lastAppliedDate` (which `recurringOccurrences` does honour). Nothing deactivates a consumed `once` or an expired template. Reproduced: an applied `once` income of 5000 on a 300/mo envelope yields `covered = 5000` → `monthly <= 0.005` → the envelope is pushed into `allowanceInfo.skipped` and projects **no allowance in any month**; a monthly 300 with `endDate` seven months ago still reports `covered: 300`. The posted occurrence is also excluded from `spentThisMonth`. Both "One-time future" and End date are ordinary form options (L5857, L5869). **Fix:** one predicate, e.g. `recurringCoversEnvelope(rec)` = active AND `schedule !== 'once'` AND (`!endDate || endDate >= start of current month`), used in *both* `recurringMonthlyForEnvelope` and the `coveringRecs` loop so decision #23's netting and decision #34's spent-this-month exclusion stay in step. The `once` occurrence itself is still projected by `recurringOccurrences`, which is the right place. Add harness cases to `audit/run-audit.mjs` for applied-`once` and past-`endDate`. Residual (acceptable): a recurring whose `endDate` is inside the horizon but still future keeps netting for the months after it ends. _Cross-check: NEW concrete bug in the recurring-coverage area that roadmap #21 already flags as conceptually muddled; this one is a plain defect, not a design question._

## Medium

### Logic and correctness

**Remaining user-initiated mutations without an undo snapshot** — logic + structure (four findings consolidated), `pocket-envelopes.app:4843-4854, 3676-3697, 3585-3605, 5919-5976, 5992-5996, 4092-4178`
Same mechanism as the Fund finding at lower frequency: (a) **Move funds** `tr_save` (L4843-4854) pushes a `transfer-envelope` with no snapshot — its sibling `ret_save` (L4274) does snapshot; Move funds is the sanctioned way out of the reserve (decision #33). (b) **Update value** `iv_save` (L3676-3697) books a "Market adjustment" tx with no snapshot; a mistyped 142500 for 14250 flows straight into net worth, the daily snapshot and the forecast. (c) **editAccount** `f_save` (L3585-3605) rewrites `openingBalance` / `includeInNetWorth` in place — note `a.name` is written at L3586 *before* the name check at L3587, so the snapshot must precede that line or read into a local. (d) **editRecurring** `r_save` (L5919-5976) can reset `lastAppliedDate` to `startDate − 1` when the start is moved earlier (L5964-5968), re-surfacing months of occurrences as due, and can change type/amount/accounts. (e) **toggleRecurring** (L5992-5996) flips `active`. (f) **editEnvelope** snapshots only inside the `adjustmentTx` branch (L4128-4130), so ticking "Reserve envelope" — which clears `isReserve` on every other envelope (L4155) and thereby moves the sweep destination — is not undoable. **Fix:** `pushUndo(label)` after each handler's validation early-returns and before the first mutation: `\`Move ${fmt(amt)} between envelopes\``, `\`Update "${a.name}" value by …\``, `id ? 'Edit account' : 'Add account'`, `id ? 'Edit recurring' : 'Add recurring'` (after the transfer from/to validation at L5935-5952), `'Pause/Resume recurring'`, and hoist editEnvelope's call out of the adjustment branch (keep the adjustment label when there is one, and place it after the `isNaN` checks at L4137-4142 so a refused save leaves no stray entry). Attach the Undo toast action as `deleteAccount` (L3651) already does. _Cross-check: all new concrete bugs inside the tracked undo area._

**Close-out sweeps (and any envelope transfer out) are reported as "Spent" — but resets are not** — correctness + logic (merged), `pocket-envelopes.app:4620, 3751`
`envelopeMonthSummary` adds every `transfer-envelope` outflow to `spent` (L4620), contradicting its own header comment ("Spent = sum of expense tx.amount … Funded = … plus NET envelope-to-envelope transfer in"); `envelopeMonthSpendMap` (L3751) does the same. The close-out `sweep` action posts exactly such a transfer dated the last day of the closed month (payee "Close-out sweep"), while `reset` posts a one-sided expense that `isCashflowTx` excludes. Reproduced with the real functions: budget 300, real spend 250, sweep 50 → `spent = 300`, variance 0, "on budget". So Reports → Budget vs actual for every closed month with sweep envelopes hides every underspend, a re-opened close-out shows the same inflated figure, the reserve row (budget 0) shows every overspend it covered as "over", and a mid-month Move funds out advances the envelope card's pace bar toward `over` though nothing was bought. The forecast's `spentThisMonth` counts only `expense` rows, so card and forecast disagree by any transfer out. **Fix (minimum):** skip `tx.payee === 'Close-out sweep'` (already in `BOOKKEEPING_PAYEES`, L1613) in both accumulators — the app's own bookkeeping must not read as spending (decision #26's principle). Whether *all* `transfer-envelope` outflows should stop counting is a design question (the `envelopeMonthSpendMap` comment says "transfers out count" deliberately); if they keep counting, apply the same rule in the forecast's `spentThisMonth` so the three views agree. Add a harness case: real spend 250 + sweep 50 must report spent 250.

**Reports and envelope cards count future-dated (scheduled) transactions as already spent** — correctness, `pocket-envelopes.app:6726-6744, 3745, 4610-4630`
`reportsAggregates` has no upper bound at today — month buckets and the 30-day windows test only `tx.date >= cutoff` — so a row dated the 25th counts in this month's income/expense and the "last 30 days" doughnuts on the 10th. `envelopeMonthSpendMap` filters only `tx.date > last`, so the card's "spent this month" and pace bar include scheduled rows that `envelopeBalance` explicitly excludes (decision #40). The verifier found a third site the reviewer missed: `envelopeMonthSummary` has the same `<= last` window and drives `budgetVsActualHTML`'s current-month bar. The forecast's `spentThisMonth` caps at today and separately projects the same row at its future index, so card and forecast disagree by the scheduled amount. **Fix:** hoist `todayISO()` once and `continue` on `tx.date > today` in `reportsAggregates`, `envelopeMonthSpendMap`, and `envelopeMonthSummary`'s `spent`/`funded` accumulators (leave its month-end `balance` alone — it is a no-op for past months). If future rows are wanted in Reports as a projection, show them as a separate "scheduled" figure. _Cross-check: new concrete bug in the decision #40 area._

**Reports 12-month table drops and duplicates months whenever today is the 29th–31st** — correctness, `pocket-envelopes.app:6709, 1349`
`reportsAggregates` builds its 12 keys with `addMonths(today, -i)`, the plain `setMonth` wrapper the file's own comment above `addMonthsAnchored` warns about. Reproduced: today = 2026-03-31 yields `2025-05 2025-05 2025-07 2025-07 2025-08 2025-10 2025-10 2025-12 2025-12 2026-01 2026-03 2026-03` — five months duplicated, five missing; 29 and 30 March still drop February. Because L6726/6734 use `months.find(...)`, a duplicated key's totals land on the first copy and the second row/column stays zero, while the missing months' transactions vanish from the table, the tag columns and the chart. Roughly nine days a year, self-correcting the next day, no stored data touched. **Fix:** anchor before stepping — `new Date(today.getFullYear(), today.getMonth() - i, 1)` (or `addMonthsAnchored` from a day-1 base). Consider renaming the unanchored `addMonths` so the trap is visible; its other caller (`firstPendingOccurrence` horizon) is harmless.

**A save completing while a newer edit is pending clears `dirty`, so `flushNow()` drops the last edit on tab close and the chip says "saved"** — logic, `pocket-envelopes.app:1038-1071, 1119-1136`
`writeFile` serialises at L1038, awaits the PUT, then sets `dirty = false` (L1067) unconditionally. Sequence: edit A → timer → PUT(A) in flight → edit B (`saveDirty` sets `dirty = true`, arms a new timer) → PUT(A) resolves and clears `dirty` → user switches app before the second timer fires → `flushNow` returns on `!dirty`, and the `beforeunload` guard at L7413 is suppressed too, so the loss is fully silent and the chip reads "saved". The window is the PUT round-trip — trivial on loopback, realistic on a phone through `tailscale serve`, which is exactly where decision #9's flush handlers matter. **Fix:** a save generation: `let saveGen = 0;` — `saveDirty()` does `saveGen++`; `writeFile` captures `const gen = saveGen` before serialising and only clears `dirty` / shows "saved" `if (gen === saveGen)`. Preferred over the "clear dirty early, re-set on failure" alternative because the latter makes `flushNow` no-op during an in-flight non-keepalive PUT.

### Error handling

**Two PUTs can be in flight with the same `If-Match`: `flushNow()` during a pending save yields a spurious 409 against the user's own write** — error-handling, `pocket-envelopes.app:1033-1067, 1119-1124, 1131-1136`; `serve.py:264-274`
No in-flight guard in `writeFile`. `saveDirty`'s timer fires PUT#1; `serverEtag` is only refreshed on response. Backgrounding the tab during that round-trip makes `flushNow` see `dirty === true` and issue PUT#2 with the pre-save ETag; whichever the server processes second is refused (reproduced: identical body, 409). `handleConflict` then opens "Data changed on server" although this tab was the only writer; "Overwrite" force-writes identical data, "Keep working" leaves auto-save paused for no reason. On a phone over the tailnet "type, wait a second, switch app" is routine, and a false conflict dialog trains the reflex the real one must not create. **Fix:** a module-level in-flight promise; if one is pending, await it and re-check `dirty` before issuing a new PUT (or coalesce with a `writeAgain` flag and let completion trigger one follow-up with the fresh ETag). `flushNow` does the same. Decision #30 is preserved — a genuine cross-device write between the two PUTs still 409s because the follow-up carries the new tag. Residual: after `pagehide` the coalesced follow-up may never run (already accepted in the keepalive comment). _Cross-check: adjacent to roadmap #11's open "nicety" (BroadcastChannel ping) — same-tab rather than cross-tab, but the same self-conflict family._

**The welcome screen's "Create new budget" is offered after a FAILED load, not only when the server says there is no file** — error-handling, `pocket-envelopes.app:821-848, 1018-1025, 2678-2697`; `serve.py:113-120`
`loadFromServer` returns `false` for four outcomes — fetch threw, non-ok status, `X-Data-New`, parse/validation failure — and all leave `data` null, so `render()` shows the same welcome screen whose primary button calls `newFile()` → `data = emptyData(); writeFile()` with no confirm and no check of how the load ended. On the network paths `serverEtag` is null so the PUT carries no `If-Match` and the server accepts it; on the parse-failure path `serverEtag` was already set to the *existing* file's tag, so it matches. Decision #31 documents that a stopped backend behind `tailscale serve` is a resolved 502 with the shell served from cache — so this screen is precisely what the user sees then, one click from replacing the budget. `.bak.0` keeps the prior contents, but the toast says "Created finance-data.json on the server" as if it were a first run. **Fix:** `loadState = 'new' | 'failed'` set in `loadFromServer`; on `'failed'` render a distinct state ("Could not load your data — Retry / Import") without the Create button, or have `newFile()` refuse unless `loadState === 'new'`. Keep Import available as the deliberate "this file wins" route (decision #30).

**Recurring save does not require a start date; a cleared date input persists `lastAppliedDate = "NaN-NaN-NaN"`** — error-handling, `pocket-envelopes.app:5926, 5964, 5969-5973`
`r_save` validates name and amount but never `startDate`. A cleared `<input type=date>` yields `''`; for a new entry L5964 computes `isoDate(addDays(parseDate(''), -1))` and stores the literal string `"NaN-NaN-NaN"`, which survives `validateData`, `migrate` and PUT. The verifier found it worse than claimed: every watermark-advance site compares ISO strings, and `"NaN-NaN-NaN"` sorts *after* every real date, so the watermark never advances — each ⚡/review apply posts another real transaction while the entry stays "due today", moving with the calendar, and editing the recurring with a valid date does not heal it (L5970-5972 compare against Invalid Date → false). Only delete-and-recreate clears it. **Fix:** after the amount check, `if (!out.startDate) { toast('Start date required'); return; }` and `if (out.endDate && out.endDate < out.startDate) { toast('End date must be after the start date'); return; }`. Optionally have `migrate()` delete a `lastAppliedDate` not matching `/^\d{4}-\d{2}-\d{2}$/` so affected files fall into the existing `undefined → today` branch.

**Settings → Locale accepts any string; an invalid BCP-47 tag is saved before render and blanks every data tab on every subsequent load** — error-handling, `pocket-envelopes.app:7080, 1325-1346`
The `s_loc` handler stores the raw value (no trim, no validity check) and calls `saveDirty()` before `render()`. `fmt()`'s catch re-constructs the formatter with the same locale, so an invalid one throws from inside the catch; `fmtNum`/`fmtDate` have no guard. `el_GR` (the underscore typo for the very example the help text suggests) and `de-DE ` (trailing space) both throw. The 1.2 s debounce persists it; after reload every tab that formats a figure throws inside `render()` and `#main` stays empty — on every device sharing the file, silently (no toast). The verifier corrected one point: the Settings tab itself contains no `fmt` call and the nav wiring runs before init, so the user *can* reach Settings and retype the locale — no hand-editing needed — but nothing points them at the cause. **Fix:** in the `s_loc` handler trim and `try { new Intl.NumberFormat(v); } catch { toast('Locale: not a valid language tag (e.g. en-US, el-GR)', 3500, 'error'); e.target.value = data.settings.locale; return; }` (mirroring `s_fcfloor`'s reject-and-restore). Also make `fmt`'s catch fall back to `DEFAULT_LOCALE` as well as EUR, and guard `fmtNum`/`fmtDate` the same way so a hand-edited file cannot take the UI down either.

**serve.py: an `OSError` during read or write of the data file is uncaught — the connection is dropped with no response and the client reports "server unreachable"** — error-handling, `serve.py:132-138, 141-166, 236-242, 262-275`
`_read_data` catches only `FileNotFoundError`; `_rotate_backups` and `_write_data` catch nothing; `_put_data`/`_get_data` call them bare. On Windows, `os.replace`/`shutil.copy2`/`open` raise `PermissionError` whenever another process holds the file (backup agents, AV, an editor); any host can raise ENOSPC. Reproduced: with `_write_data` raising `PermissionError`, a PUT got `RemoteDisconnected` and a traceback on stderr. The browser's `fetch()` rejects, so `writeFile` toasts "Save failed — server unreachable" and `loadFromServer` "is serve.py still running?" — both wrong; the status-aware `!res.ok` branches never fire. A failure between rotation and `os.replace` also leaves the rotation half-shifted with no fresh `.bak.0` and a stale `.tmp`. Under the installer stderr goes to `server.log` where nobody looks. **Fix:** in `_put_data`, inside the lock, `try: _write_data(body) except OSError as exc: return self._send_error_json(500, 'could not write data file: %s' % exc)` (include the `_read_data` call at L264 in the guard); same around `_read_data` in `_get_data`. The client already renders "Save failed (server said 500)". Optionally remove `TMP_FILE` in the except path. Stdlib-only, bypasses no `_write_data` path.

### Security

**serve.py's private-path guard checks the URL before percent-decoding, so `/finance%2Ddata.json`, `/%2Eclaude/…`, `.bak` and `.log` files are served** — security, `serve.py:70-82, 176-177, 194-211`
`_route()` never calls `urllib.parse.unquote` (urllib is not imported), so `_is_private_path()` tests the still-encoded components; `SimpleHTTPRequestHandler.translate_path` decodes *afterwards*. Reproduced on a scratch copy: `/finance-data.json` → 404 but `/finance%2Ddata.json` → 200 with the full budget; `/finance%2Ddata.bak.0` → 200; `/%2Eclaude/launch.json` → 200; `/serve-daemon%2Elog` → 200; by extension `/%2Egit/…` objects from a checkout run in place (and the `private-archive` branch's commit bodies quoted real figures). The docstring (L41-44) and decision #29 promise these are unreachable except through `/data`. The audience is the same one that can already `GET /data` unauthenticated, so this widens the file set (five older budgets, logs, `.claude/`, `.git/`) rather than the population — medium. **Fix:** decode before deciding — build `parts` from `urllib.parse.unquote(path_only)` and normalise with `posixpath.normpath` so `/./` and `//` collapse as `translate_path` will. Better still, invert the model: allowlist the handful of files the app needs (`pocket-envelopes.app`, `manifest.webmanifest`, `sw.js`, `icons/`, `vendor/`) and 404 everything else, so a future bypass fails closed. Add a regression test requesting the encoded forms.

**Record ids and `tx.type` from the data file are interpolated unescaped into HTML attributes — a crafted `finance-data.json` or imported file executes script** — security, `pocket-envelopes.app:3037, 3048, 3062, 3425-3441, 3454-3460, 3816-3822, 4944, 4948, 5024-5026` (64 sites)
`esc()` is applied consistently to names, payees, notes, tags and categories, but every `data-*="${x.id}"`, `value="${a.id}"` and `class="… ${tx.type}"` / `title="${typeLabel}"` is raw (`grep` returns 64 raw id sites and zero escaped ones; L3037 also emits `rec.type` as a bare text node). `validateData()` checks list/object shapes only, never `id` or `type`. There is no CSP. An envelope id of `e1" onmouseover="…` passes parse → validate → migrate and reaches `main.innerHTML`; reproduced on the scratch server via both an id and `tx.type`. `uid()` and the demo ids are always safe, so the only source is a foreign or hand-edited file — Settings → Import, a restored backup, or the server file written by any peer that can reach the port. Once running, the script is same-origin: it can read every `envBudget_bak_*` slot and `PUT /data` without `If-Match`. The README now encourages moving the JSON between devices and restoring shared backups. **Fix:** close it at the existing chokepoint, not at 64 sites — in `validateData()` require, for each entry of accounts/envelopes/transactions/recurring, `typeof x.id === 'string' && /^[A-Za-z0-9_-]+$/.test(x.id)` (covers `uid()`, `demo_*`, `__fundProbe`) and for transactions/recurring `TX_TYPE_LABEL[x.type]` (or the recurring type set); refuse with the existing "refusing to load a corrupt file" toast (decision #19's contract). Additionally wrap the two `type` renders (L3037, L5026) in `esc()` as defence in depth. Do not weaken `esc()` or move off string templates.

**serve.py never checks the `Host` header, so a DNS-rebinding page can read and overwrite `/data` through the loopback bind** — security, `serve.py:217-233, 236-280`
Routing is on `self.path` alone; no `Host` or `Origin` header is ever inspected, there are no CORS headers and no `do_OPTIONS`. An ordinary cross-origin page is blocked by the browser — but DNS rebinding sidesteps CORS: a page at `http://attacker.example:8765` whose hostname is re-pointed at 127.0.0.1 after first load is same-origin with its own later requests, which arrive carrying `Host: attacker.example:8765` and are answered — full budget on GET, forced overwrite on PUT (missing `If-Match` is accepted by design, L119-120). Chrome's Private Network Access blocks most of this; Firefox and Safari do not, and `serve-daemon.cmd` keeps the port answering permanently as SYSTEM (decision #32), so the window is "whenever the user is browsing". Decision #29 makes reachability the whole access-control story; a Host check is the one stdlib-only measure that keeps "the port" meaning the machine's own users rather than any website open on it. **Fix:** before routing, compare the `Host` hostname (strip `:port` and IPv6 brackets) against `localhost`, `127.0.0.1`, `::1`, plus an optional comma-separated `ALLOWED_HOSTS` env for the `tailscale serve` name and a LAN hostname; answer anything else `421` with a JSON error. **Ship it with `ALLOWED_HOSTS` wired into `serve-daemon.cmd` and the README multi-device section in the same commit** — `tailscale serve` forwards `Host: <machine>.<tailnet>.ts.net`, so without that the always-on task would answer 421 to every phone after upgrade. No auth is introduced; the local-only invariant stands.

### Performance

**`fmt()` / `fmtDate()` / `fmtNum()` construct a new `Intl` formatter on every call; every table cell pays 23–39 µs** — performance, `pocket-envelopes.app:1325-1346, 5003`
Each helper does `new Intl.NumberFormat(...)`/`new Intl.DateTimeFormat(...)` then `.format()` once; nothing caches (`txDayLabel` builds its own per day header at L5003). Construction is the expensive part. Reproduced in Node 24 on 3000 values: `fmt` 80.8 ms uncached vs 1.6 ms cached; `fmtDate` 138.6 ms vs 3.0 ms. These sit inside every row renderer (`txDataRow`, `txRow`, `txDateCell`), the envelope cards, Reports tables, Recurring rows, the Fund modal rows and the Chart.js tick callbacks, and the whole cost is paid again on every search keystroke. At multi-year data sizes the fix roughly halves a keystroke-render (the `innerHTML` parse of thousands of rows is the other half). **Fix:** memoise formatter instances keyed by their inputs — a module-level `Map` and `_numFmt(locale, currency)` / `_dateFmt(locale, opts)`; `fmt` becomes `try { return _numFmt(locale, currency).format(n); } catch { return _numFmt(locale, 'EUR').format(n); }` (a bad currency still throws at construction, before any cache entry is stored, so the fallback is preserved). Keyed on the settings values, so a locale/currency change simply produces a new entry; nothing to invalidate. _Cross-check: same spirit as roadmap #19 (memoise balances) but a separate, cheaper win._

**Transactions search box rebuilds the whole table synchronously per keystroke, and the filter formats every amount with a fresh `Intl` instance** — performance, `pocket-envelopes.app:4889-4907, 5068-5085`
`filterTxs`'s free-text branch evaluates `fmtNum(t.amount).includes(q)` (L4906) for every transaction that fails the cheaper tests — nearly all of them for a normal query — constructing a formatter per row (~90 ms at 3000 rows in Node). `filt` is bound `oninput` with no debounce, and each call does `filterTxs()` → `txRowsHTML(rows)` for the *entire* matching set (no pagination anywhere in `renderTransactions`) → `innerHTML` → `bindRows()` (four `querySelectorAll` passes) → `updateBulk()`. Typing a nine-letter payee replays all of that nine times; the users with the most history get the worst experience. **Fix, in payoff order:** (1) the formatter cache above, plus gate the `fmtNum` term on `/\d/.test(q)` — a query with no digit can never match a formatted amount; (2) debounce only `#txFilter` (~120 ms), keeping the selects/dates immediate; (3) replace the four rebinds with one delegated `click`/`change` listener on `#txBody` dispatching on `e.target.closest('[data-edit-tx],[data-copy-tx],[data-del-tx],[data-sel-tx]')`. None of these touch filtering semantics or the module-level `txFilter` state.

### Logic and correctness

**`migrate()` stamps a version-less file as current before the versioned steps run** — logic, `pocket-envelopes.app:904, 955-958`

**`applyDueRecurring` and `applyRecurringInstanceNow` advance the watermark without pruning `skippedDates`** — logic, `pocket-envelopes.app:2117-2132, 5808-5825`

**Keepalive size cap counts UTF-16 characters, not bytes, so a save on tab close can be rejected silently** — correctness, `pocket-envelopes.app:1047`
`useKeepalive = keepalive && body.length < 60000` measures code units; the 64 KiB keepalive budget is on the UTF-8 body. Greek letters are 2 bytes, `€` 3, so a body just under 60k chars with ~10% non-ASCII exceeds 65,536 bytes; Chrome rejects before sending, the catch returns false, and on `pagehide` there is no one to see the toast — a deterministic loss in a narrow band (bodies *above* the char cap fall back to a normal fetch and usually complete). The comment at L1044-1046 shows a byte cap was intended. **Fix:** `const bytes = new TextEncoder().encode(body); const useKeepalive = keepalive && bytes.length < 60000;` and send `bytes`.

**Closing an older month from Settings moves `lastClosedMonth` backwards and re-arms the close-out banner** — correctness, `pocket-envelopes.app:4639, 4799, 7110-7114, 4589-4596`
`showCloseOut(forcedYM)` writes `data.lastClosedMonth = ym` unconditionally in both branches, and Settings invites re-opening "any prior month". Re-closing June after August sets the cursor to `2026-06`; `closeOutDue` sees `last < prevYM` and offers August again; Settings' "Last closed month" line is wrong. ### Error handling

**`loadFromServer` reads the response body outside its try/catch — a body-read failure rejects the init IIFE and leaves the page blank with no toast** — error-handling, `pocket-envelopes.app:837, 7659-7663`
Only `fetch()` is inside the try; `await res.text()` is not, and the init IIFE has no catch and no `unhandledrejection` handler exists. **serve.py: a PUT whose body arrives short blocks the handler thread forever** — error-handling, `serve.py:169, 254`
`Handler` sets no `timeout`, so `rfile.read(length)` is unbounded; a keepalive PUT cut off at tab close or a phone that sleeps mid-upload parks the thread for the life of the process. ### Security

**`?view=` is spliced into a `querySelector` string; a quote in the parameter throws and skips service-worker registration** — security, `pocket-envelopes.app:7634-7654, 7683-7687`
`applyUrlParams` returns `params.get('view')` raw; the boot IIFE runs ``document.querySelector(`nav.tabs button[data-view="${urlOpts.view}"]`)``. ### Accessibility and UX

**Conflict status chip is a click-only `<div>`: not focusable, not a button, and colour-only on narrow phones** — a11y-ux, `pocket-envelopes.app:733-735, 117, 151, 1280-1288, 7364-7368`
The chip has no `role`/`tabindex`/keydown handler; at ≤460 px the label is hidden for non-conflict states and the text lives only in `title`. The conflict label also stays visible on narrow phones by design (L151 is `:not(.conflict)`), and unreachable/non-ok states fire aria-live error toasts; only the transient 1.2 s "unsaved" is dot-only. **Fix:** render the chip as `<button type="button">` disabled when `!conflictPending`, add an `.sr` span carrying the state text, and correct the comment.

**Opacity-dimmed text falls below AA contrast: scheduled-transaction amounts, onboarding step blurbs** — a11y-ux, `pocket-envelopes.app:319-320, 550-551, 559`
`tr.tx-future td.num { opacity: .7 }` on top of `--text-dim` gives 3.65:1 dark / 3.12:1 light for 13 px figures (and the rule outranks `.neg`/`.pos`, so every scheduled amount loses its sign colour too); `.ob-done` (.72) and `.ob-locked` (.55) blurbs land at 3.41 / 2.97 and 2.56 / 2.18. Plain `--text-dim` passes (6.06 / 5.96). `.ob-locked` is arguably a disabled-state cue, but the blurb is instructions, not the control. WCAG 1.4.3. **Fix:** drop the opacity on text cells (the dashed "scheduled" badge plus `--text-dim` already carry the state); confine the onboarding opacity to `.ob-num`/the button.

**Envelope "⋯" menu uses `role=menu`/`menuitem` without arrow-key navigation, and `.menu-item` has no visible focus indicator** — a11y-ux, `pocket-envelopes.app:3884-3891, 3915-3929, 425-427, 503-513`
Only Escape and outside-click are handled; screen readers switch mode on `role=menu` and users try arrow keys that do nothing. `.menu-item:focus-visible { background: var(--bg-3) }` is ~1.15:1 on the menu surface in dark (lower in light), and the global outline rule does not include `.menu-item`. Tab/Enter/Escape still work, hence low. **Fix:** either drop the menu roles (a disclosure with plain buttons is valid and Tab-navigable) or add ArrowUp/ArrowDown on `.menu`; add `.menu-item:focus-visible` to the outline rule at L503-513.

**Pin button and toast Undo button are under the 24 px minimum target size** — a11y-ux, `pocket-envelopes.app:198-199, 186-189, 594-596, 3428`
`.pin-btn` is ~21×15 px (icon + 6 px right padding, no min size), immediately adjacent to the drill link with no gap, and excluded from the `(pointer: coarse)` enlargement the file already applies to `.btn.sm`/`.btn.icon` "because WCAG 2.5.8 wants ≥24px" (comment at L185). **Transactions table renders an empty `<tbody>` with no message when there are no rows or no filter matches** — a11y-ux, `pocket-envelopes.app:4981-4983, 5008-5018, 5078, 4919`
Accounts (L3423), Recurring (L5722), Envelopes (L3793) and the dashboard Recent list (L3093) all have an empty state; Transactions does not, and it is the one most likely to be legitimately empty because drill-through and `?acc=`/`?env=` URL params (decision #39) pre-fill the filter. **Conflict-dot pulse animation has no `prefers-reduced-motion` guard** — a11y-ux, `pocket-envelopes.app:118, 166, 396`
